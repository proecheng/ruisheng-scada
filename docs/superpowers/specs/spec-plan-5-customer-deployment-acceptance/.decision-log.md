## Decisions

- 当前 README、实际 Compose 和已通过的部署契约测试优先于 `docs/系统架构说明.md` 中“生产不使用 Docker”的过时描述；后者未作为 companion。

- 真实通知仍遵循告警规格的 Ask First 边界，本规格只定义授权后的条件验收，不授权凭据使用。

## 2026-08-19 — Adversarial Review

- 条件项允许凭“书面豁免或后续责任人”通过，使实际失败可绕过 Go/No-Go。
- 固定默认密码只是生产 seed 风险的一部分；迁移入口还会无条件创建 Demo 租户、用户、设备和点位。
- “开放网络前人工改密”仍存在启动到改密之间的暴露窗口，不能满足安全首次启动。
- 应用 `latest` 和 Redis `7-alpine` 是可变标签，与不可变候选身份约束冲突。
- 两次 `docker save | gzip` 的字节或 SHA-256 未必可复现，原 G0-03 的“制品稳定”不可判定。
- 根/离线 Compose 的“功能等价”没有归一化比较方法和允许差异清单，容易靠人工忽略漂移。
- 现场直接修改交付 Compose 会破坏签名与复现性，原规格未定义独立站点 override。
- 缺少一个开测前批准的站点参数载体，性能、网络、RTO/RPO、真机和签署责任均悬空。
- 至少 24 小时持续运行是合理建议但不是已确认需求，原规格把未批准假设写成硬门槛。
- 当前串口配置只支持端口和波特率，原规格却要求验证校验位、数据位和停止位，没有处理能力缺口。
- 在真机链路直接注入 CRC、截断和乱序帧可能影响设备安全，原矩阵未限定隔离台架。
- 备份验收只提 schema 和抽样数据，遗漏数据库角色/RLS、TimescaleDB 扩展、站点配置、密钥保管和空白机恢复。
- 固定从 `deploy-v0.1.0` 升级未确认该站点实际版本和旧制品可用性，也未覆盖中断后重复迁移/bootstrap。
- 当前 Nginx 代理全部 `/api/`，GW health 监听所有地址；原网络门槛没有从不同网段实测管理端点暴露。
- 告警事件使用数据库 UTC 和时间窗口，但原规格没有主机时钟源、允许偏差和时区验收。
- 原规格没有日志轮转、磁盘/卷/WAL 容量与告警门槛，长时间真机和中断测试可能因磁盘耗尽失真。
- 当前 GW WAL 只重放遥测行且绕过告警引擎，原“断网后无 P0 告警遗漏”在数据库中断场景下没有实现依据。
- 遗留双跑只规定天数和差异阈值，遗漏静态配置/历史迁移范围、来源区分及避免重复控制/通知的隔离路径。
- 只有 SHA-256 不能验证发布者身份，原候选契约缺少可验证的签名或受认证分发信任锚。
