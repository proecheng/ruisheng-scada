目标机 `WIN-OAUCM8UQUGH / 100.109.90.21`；当前版本 `deploy-20260907.1`。

本表是旧软件的**候选映射与诊断结果**，不是已投产点表。BCMM、CBMM 是两种待辨认的型号候选，46行不代表安装了46个物理点。所有地址均为十进制、Modbus请求中的零基地址。

已用3次FC3只读请求覆盖0..5、6..26、27..35，零重试、零设备寄存器写入。响应CRC均有效。原始帧随后经新部署代码的采集解码与批量写入链路，在目标机独立测试数据库回放并回读。

## 阅读口径

- “原值R/H”是同一请求地址的原始无符号数在实时表/历史表各1条且回读一致；不同型号共用地址时引用同一条原值证据，不重复计算物理采集量。
- “模拟R/H”是该候选行使用受支持的无符号“字”类型及旧倍率进行两次模拟输入，实时表保留最新1条、历史表保留2条；不证明物理单位、实际倍率或有符号解码正确。
- 所有42个FC3候选的旧类型均为`s16`。新版本对这个尚未支持的类型逐项拒绝，避免把`0xffff`误写为正65535；这不是已经支持负温度。
- 旧倍率和单位只作资料记录。原值栏不换算、不宣称电压/温度等工程值有效；全表均不允许直接导入生产。

## 结论与下一步

36个请求地址对应的原值均已入库并准确回读；42个候选寄存器的模拟换算与存储测试、42项不支持类型拒绝、4项冲突开关量拒绝均通过。

但三个区间的响应都以`[3, 0]`开头，且旧表换算出现1000℃、9.9Hz等疑点。Modbus读响应不回显起始地址，CRC有效只能确认帧传输完整，不能证明设备按请求起点返回了正确寄存器。现有证据不足以认定是旧点表错误还是设备地址响应行为不同；不能据此随意改倍率或固件。

下一阶段应先制定并批准有界的重叠区间/地址相关性只读测试，结合原固件或协议资料确认模型、映射、符号和倍率，再处理适用的FC1候选，最后导入确认后的点位并验收连续生产采集。本次没有启用连续轮询，也没有创建生产账号、设备或点位。

数据库：`test_point_pipeline_20260907_d135806d`，保留用于复核。完整实验共实时126条、历史168条，其中物理原值各36条；其他记录为明确标记的诊断用例。
