## Decisions

- B-04 规格限定结果而不替站点选择具体防火墙或 TLS 产品；绑定、宿主机 ACL、上游 ACL 和认证管理代理可组合使用，但必须通过实际源网段探测证明效果。
- HTTP 只在 Profile 明确批准的隔离可信网中允许；共享或不受信路径上的认证、令牌、WebSocket 和控制必须使用 HTTPS/WSS 且无直达旁路。
- API `/api/health/*` 与 GW 管理端点当前无应用鉴权，因此网络控制是现阶段的强制边界，不能把未来鉴权当作当前证据。
- Nginx 代理全部 `/api/`，所以 API 未发布宿主机端口不等于健康/指标端点不对用户暴露；目标矩阵要求单独隔离管理路径。
- GW 对已登记设备的源 IP 检查属于应用纵深控制，不替代 `gw:5020` 的网段 allowlist；设备协议也不被假定提供传输加密。
- 当前 `/ws?token=` 会让令牌进入请求目标。规格允许改变握手或明确去除日志查询参数，但要求用专用令牌扫描全部证据日志，不能只检查 Nginx 配置文本。
- 通配绑定只有在 Profile 批准且等效网络控制经正反向实测时才允许；这保留多网卡和站点防火墙实现空间，同时阻止默认公开。
- B-04 文档完成不关闭阻断项；Profile 审批、实际控制、四类网段探测和三方签署缺一不可。
