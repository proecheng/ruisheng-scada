## 给设备固件工程师的核查与改进意见

请先定位出错边界，再改具体逻辑；目前没有证据要求更换整块采集板。软件平台保持从站1、9600/8N1、FC03、起始0、38寄存器、5秒周期，最多同轮补读一次。不要通过放宽CRC、把残帧拼成数据或继续加重试掩盖设备侧异常。

### 1. 优先检查发送长度、CRC与RS485方向切换

- 固定请求为 `01 03 00 00 00 26 C4 10`，共8字节。正常响应必须为 `01 03 4C`、76字节数据、2字节CRC，共81字节。
- 本次实际收到 `01 83 04`，缺CRC。若本意为功能码03的设备故障异常码04，完整报文必须是 `01 83 04 40 F3`，共5字节。检查正常和异常路径是否共用完整的长度/CRC处理，禁止使用字符串长度计算二进制报文长度。
- 发送缓冲应在DMA/中断发送完成前保持有效且不被覆盖；核对DMA长度单位、缓冲索引与中断重入。对比CPU交给驱动的字节数、实际TX引脚字节数和USB端收到的字节数。
- 核对DE/RE时序。若MCU有独立TC标志，关闭发送使能应以最后一个停止位真正发送完成为准，不能仅凭TXE、DMA传输完成或发送API返回。按实际芯片参考手册实现，不把这些事件等同。

### 2. 检查UART接收与错误恢复

- 核对板端、转换器及软件实际均为9600/8N1，检查时钟源、波特率分频误差和供电。保持当前通信参数做对照。
- 检查UART的FE/NE/ORE/PE处理及清标志顺序，错误后是否可靠重新挂接DMA/中断接收，环形缓冲是否溢出或读写指针错位。
- 收到半帧、坏CRC、地址不符时，应丢弃该帧并可接收下一条相同请求，不能让Modbus状态机停留在等待旧帧状态。按串口字符时间处理RTU帧间隔，不依赖主循环碰巧及时运行。
- 查找长时间关中断、阻塞采样/Flash操作、看门狗复位等会打断Modbus服务的路径。记录最长响应耗时，确认有效响应在现有1秒等待窗口内完成；目前正常响应远小于1秒。

### 3. 增加最小定位记录

使用独立调试口、SWD/RTT或内部环形缓冲记录，不向当前Modbus串口混入打印文本。每个请求记录单调时间戳与本地序号，以及：RX完整8字节与CRC结果、UART错误计数、Modbus处理开始/结束、准备发送长度与完整报文、DMA完成、UART TC、DE下降、接收重新启用、设备复位原因。首次请求与1.2秒左右后的相同补读都应留下记录。

先用逻辑分析仪同时观察MCU RX、TX和DE；条件允许时，再用合适的差分测量核对RS485 A/B。按以下证据确定修改对象：

| 现场观测 | 优先处理对象 |
| --- | --- |
| USB已提交正确请求，MCU RX引脚没有完整正确请求 | 转换器发送、线缆/接线、供电或板端收发器 |
| MCU RX收到完整正确请求，固件没有产生响应 | 接收状态机、中断/DMA恢复、任务阻塞等板端固件 |
| 固件准备完整响应，MCU TX或DE提前结束 | 板端UART/DMA发送与DE时序 |
| MCU TX与DE正确，A/B波形或另一端字节异常 | 收发器、参考地、终端/偏置、线缆或转换器 |
| USB已收到完整有效帧，而平台没有接受/入库 | 平台接收、解析或入库软件；保留对应原始帧后修复 |

一次只改变一项，记录起止时间。修改后在相同通信条件下先复测完整响应、UART错误及补读，再从实际恢复时间开始新的连续验收段；保留本轮所有缺样与维护记录。无需第二台采集设备即可执行上述定位。
